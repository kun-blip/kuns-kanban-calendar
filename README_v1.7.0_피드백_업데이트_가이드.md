# KUN'S KANBAN CALENDAR v1.7.0

v1.6.3 기반 변경사항: Google Sheets 피드백 접수 + 새 버전 자동 알림.

## 포함 기능
- 상단 **피드백** 버튼으로 종류(기능 제안 / 버그 신고 / 디자인 개선), 내용, 선택 닉네임 작성.
- Electron 메인 프로세스가 `desktop/feedback-config.json`의 Apps Script `/exec` URL로 POST 전송. 앱 버전 자동 기록.
- 일정, 메모, To-do, 백업 데이터, 파일 경로 등은 피드백 요청에 포함하지 않음.
- 입력 제한(3~2,000자), 전송 중 중복 클릭 방지, 성공 후 1분 간격 제한.
- 기존 자동 업데이트 확인(실행 후 약 15초, 6시간 간격)은 유지. 새 버전 발견 시 Windows 알림과 앱 내 팝업(편집 중에는 자동 팝업 보류).
- **나중에** 선택 시 해당 버전 자동 팝업을 다시 표시하지 않음. 업데이트 버튼으로 수동 확인/설치는 계속 가능. 다음 새 버전은 다시 알림.
- 업데이트 다운로드와 설치는 여전히 사용자가 직접 승인해야 함.

## 설치/배포 순서 (GitHub Desktop)
1. 기존 프로젝트 폴더를 백업해 두고 이 ZIP의 내용을 GitHub Desktop 저장소 **루트**에 복사/덮어쓰기. `.git` 폴더는 삭제하지 마세요.
2. `package.json`과 `package-lock.json`의 버전은 이미 `1.7.0`입니다. 별도로 `npm version` 명령을 실행하지 않아도 됩니다.
3. **Changes**에서 변경사항을 확인하고 `Add feedback and update notifications v1.7.0`으로 Commit → Push origin.
4. **History**에서 가장 최신 커밋을 우클릭 → **Create Tag...** → `v1.7.0` → 태그 Push.
5. GitHub Actions 완료 후 Releases에 `KuunsKanbanCalendar-Setup-1.7.0-x64.exe`와 `latest.yml`이 있는지 확인.
6. v1.6.3 설치 앱에서 **업데이트** → 다운로드 → 재시작 설치. JSON 백업 권장.

## Google Sheets 접수 확인
1. v1.7.0 설치 앱의 **피드백** 버튼을 클릭합니다.
2. 테스트용 내용 하나를 보내고 Google Sheets의 `피드백` 탭에 새 행이 등록됐는지 확인합니다.
3. 작성했던 Apps Script 코드의 `doPost`가 배포된 버전에 포함되어 있어야 합니다. 수정했다면 Apps Script의 **배포 관리 → 수정 → 새 버전 배포**를 수행해야 합니다.
4. 앱에 `피드백이 전송되었어요`가 표시되더라도 시트 행이 실제 생겼는지 최초 1회 확인하세요.

## 주의
- Apps Script `/exec` URL은 Windows 앱 안에 포함되므로 **비밀로 간주하면 안 됩니다**. 악의적인 외부 제출까지 서버에서 막는 것은 아닙니다. 필요하면 Apps Script에 관리용 요청 제한·검토 프로세스를 추가하세요.
- 시트 자체는 공개하지 말고, 회사 기밀이나 개인정보를 피드백에 적지 않도록 팀원에게 안내하세요.
- `v1.7.0`으로 업데이트되면 이 버전은 본인의 새 버전을 자동 알림하지 않습니다. **다음 버전(v1.7.1 이상)**이 배포될 때 알림 기능을 검증할 수 있습니다.
- 로컬 단위 테스트만 수행했습니다. Windows 설치 및 Google Sheets 실제 접수는 사용자의 환경에서 검증해야 합니다.
