# KUN'S KANBAN CALENDAR v1.9.16 — 공유 일정·초대 이력 개선

기준 소스: **v1.9.15**. 개발 검토용으로 준비한 공유 작성자/권한 이력/잔여 상태 UI 개선을 정식 배포 패키지에 통합했습니다.

## 승인된 업데이트 패치노트

1. **공유 일정 작성자 표시** — 공유된 일정의 작성자를 확인할 수 있도록 개선했어요.
2. **공유 권한 및 초대 이력 개선** — 기존에 초대한 동료와 보기/편집 권한을 일정 편집창에서도 확인할 수 있어요.
3. **불필요한 상태 UI 정리** — 이전 상태 기능의 잔여 표시를 제거하고 일정 화면을 간결하게 정리했어요.

## 수정 상세

- 공유 작성자의 이메일을 새 공유 일정에 기록하고, 일정 카드·상세·공유 관리 화면에서 확인할 수 있게 했습니다. 기존 공유 일정에 작성자 이메일이 저장되지 않은 경우에는 임의로 정보를 생성하지 않습니다. 작성자가 이 버전으로 다시 저장하면 표시가 가능해집니다.
- 일정 편집 시 기존 참여자, 초대 대기 목록, 권한, 지난 초대 기록을 서버에서 조회하여 보여줍니다. 조회 실패 시 오류와 다시 불러오기 버튼을 표시합니다. 기존 구성원을 다시 초대하지 않습니다.
- 과거 상태 기능의 '소프트런칭/라이브' 등 잔여 상태 표기를 사용자 인터페이스에서 제거합니다. 과거 기록 자체는 삭제하지 않으며, 직접 사용·커스터마이징한 태그도 유지합니다.

## Windows CMD 배포 절차

1. 사용 중인 GitHub 프로젝트 원본 `C:\Users\master\Documents\GitHub\kuns-kanban-calendar` 을 백업합니다.
2. `KUNS_KANBAN_CALENDAR_v1.9.16_PATCH.zip` 안의 **파일과 폴더를 프로젝트 루트에 덮어씁니다**. `package.json`이 있는 폴더입니다. ZIP의 내용만 덮어쓰며 기존의 데이터/일정은 삭제하지 않습니다.
3. `RUN_v1.9.16_TESTS_CMD.bat` 실행 → 전체 테스트 통과 확인.
4. `PUBLISH_v1.9.16_CMD.bat` 실행 → 변경 파일 상태 확인 → `PUBLISH` 대문자로 승인.
5. GitHub Actions에서 Windows/macOS 작업 성공과 v1.9.16 Release 생성 여부 확인. 릴리스 생성 후 앱 자동 업데이트/재시작 시험.

Git 등록 대기 상태가 이미 존재하면 배포 스크립트는 중지됩니다. 이때는 `git diff --cached --name-only`로 무엇이 등록되었는지 먼저 확인하고, 별도로 보존할 변경이 있는지 점검하십시오. 등록 대기 상태만 해제할 때 `git restore --staged .`를 사용할 수 있으며 이 명령은 작업 폴더 파일 자체를 지우지 않습니다. `git reset --hard` 및 `git clean -fd`는 사용하지 마세요.

## 실제 사용 검수

- 계정 A가 B에게 보기만/편집 권한으로 공유 → A가 동일 일정 다시 열기 → 기존 초대·권한·대기 정보 유지 확인.
- B의 일정에서 A의 작성자 정보 확인. 구버전 공유 일정은 A가 업데이트 후 다시 저장하고 B가 새로고침한 뒤 확인.
- 이전 상태 문구 제거 확인. 실제로 사용자가 만든 동일 이름의 태그는 유지되는지 확인.
- Windows와 Mac 양쪽의 공유 동기화, 권한 변경 및 신규/기존 공유 일정 확인.

**자동 테스트가 Supabase 서버·Windows/Mac 실제 기기의 통합 동작까지 보장하지는 않습니다.** 이 패키지는 GitHub에 자동으로 배포되지 않으며, 사용자가 배포 스크립트를 명시적으로 실행해야 합니다.
