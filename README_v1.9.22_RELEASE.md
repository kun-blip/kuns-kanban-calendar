# KUN'S KANBAN CALENDAR v1.9.22 – Release

## 승인된 업데이트 팝업 문구 (그대로 적용)

### 01. 타임라인 블록 자유 배치
일정 블록을 위아래로 드래그하여 원하는 줄로 이동할 수 있도록 개선했어요. 블록 간 겹침 현상도 수정하고, 공유 일정의 우선 표시 방식을 개선했어요.

### 02. 계정별 데이터 분리
일정, 고정 메모, Daily Todo 등 개인 데이터를 로그인 계정별로 분리했어요. 로그아웃하면 이전 계정의 개인 데이터가 화면에 남지 않도록 수정했어요.

### 03. 신규 설치 데이터 초기화
처음 설치한 캘린더는 예시 일정이나 메모 없이 빈 화면으로 시작해요.

### 04. 기존 데이터 보호 및 복원
업데이트 후에도 기존 개인 데이터는 삭제되지 않아요. 이전 PC에 저장된 데이터는 본인 계정으로 안전하게 가져올 수 있도록 개선했어요.

## 꼭 읽어 주세요

- **기존 개인 데이터를 자동으로 새 계정에 합치지 않습니다.** 로그인해서 `이전 PC 데이터 가져오기`를 누르고, 서버에 동일한 데이터가 이미 없는지 확인해 주세요.
- **기존 저장 파일은 삭제하지 않습니다.** 로그아웃 상태에는 로컬 개인 데이터가 표시되지 않지만 예전 데이터 파일은 보존합니다.
- 로그인한 계정마다 일정·메모·Todo·태그·바로가기를 별도로 저장합니다.
- 같은 계정의 **Windows / Mac 양방향 동기화는 아직 실제 두 기기에서 검증하지 않았습니다.** 먼저 백업하고 테스트 일정으로 확인하세요.
- **피드백 스크린샷 전송은 Google Apps Script 서버 업데이트가 필요할 수 있습니다.** 이 릴리스의 패치노트 4개에는 포함하지 않았습니다.
- 미니 오피스 기능은 이번 배포에 포함되지 않습니다.

## 설치/테스트 안내

### Windows 소스 폴더

`C:\Users\master\Documents\GitHub\kuns-kanban-calendar`

1. 캘린더를 트레이에서까지 종료하고 **앱 데이터와 Git 프로젝트 폴더를 백업**합니다.
2. `KUNS_KANBAN_CALENDAR_v1.9.22_PATCH.zip`을 압축 해제한 뒤 위 폴더에 **내용물과 하위 폴더를 그대로 덮어씁니다**.
3. `RUN_v1.9.22_TESTS_CMD.bat` 실행 → 실패 0개인지 확인합니다.
4. `npm start`로 개발본을 실행해 UI를 확인합니다. 설치된 EXE에는 패치가 자동 적용되지 않습니다.
5. 타임라인 블록 위아래 이동, 로그아웃 시 빈 캘린더, 재로그인 복원, 신규 계정/기기 가져오기 절차를 검증합니다.
6. 확인이 끝나면 `PUBLISH_v1.9.22_CMD.bat` 실행 → 안내에 따라 `PUBLISH` 두 번 입력합니다.
7. GitHub Actions **Windows / Mac 빌드가 성공**하고 릴리스 파일이 있는지 확인합니다. 자동 업데이트 반영도 실제 앱에서 검사하세요.

## 데이터 보호

- 프로젝트 폴더를 바꿔도 사용자 일정은 해당 컴퓨터의 Electron 앱 데이터 디렉터리에 저장됩니다.
- 기존 비계정 공용 저장소와 이전 guest 저장소는 명시적인 가져오기 원본으로 보존합니다.
- 로그아웃은 저장 파일을 삭제하는 동작이 아니며, 로컬 데이터의 암호화/OS 계정 보호를 대체하지 않습니다.
- 기존 `calendar_account_snapshots` 서버 테이블은 이미 만들어진 경우 재생성할 필요가 없습니다. 배포에 별도 데이터 삭제 SQL은 없습니다.

## 배포 책임 범위

이 ZIP은 소스 및 배포 스크립트입니다. 여기서 GitHub에 게시하지 않았고, Windows/Mac 서명 설치 파일을 만들거나 실제 두 기기 동기화를 성공했다고 주장하지 않습니다.
