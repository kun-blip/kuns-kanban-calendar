# KUN'S KANBAN CALENDAR v1.9.5 — 동료 피드백 개선

## 적용된 변경

1. **게임 타이틀 수정**: 일정 등록창의 타이틀 선택 옆 `✎ 수정`으로 이름과 이미지 교체/제거. 기존 게임 ID와 연결된 일정은 그대로 유지.
2. **동료 그룹**: 일정 공유 → 동료 관리에서 그룹 이름을 넣어 연락처를 분류하고, 이름 변경/그룹 해제 가능. 일정 생성창에서 그룹 전체를 한 번에 초대 대상으로 선택 가능.
3. **동료별 자동 공유 옵션 (기본 모두 끔)**:
   - **새 일정에 기본 초대**: 새 일정 생성 시 해당 동료가 초대 대상에 미리 선택됨. 공유 전에 화면에서 제거할 수 있고, 최종 저장 시 공유 필드 확인 메시지가 나타남.
   - **이 동료의 새 초대 자동 수락**: 각 수신자가 스스로 켜야 함. 수신자 계정에 등록된, 이메일 인증을 완료한 발신자의 새 초대에만 적용. 공유 화면 새로고침/앱 포커스/주기적 갱신(2분) 시 동작하며 해제 가능.
   - 모든 개인 일정을 무단 업로드하거나 동의 없이 상대방의 자동 수락 설정을 켤 수 없음.
4. **공유 일정 상세 화면**: 제목·날짜·상태·상세 메모·관련 링크·체크리스트·게임 제목(텍스트). 편집 권한이 있는 사용자는 내용 수정, 읽기 전용은 조회만 가능. PC 알림/개인 Daily Todo/개인 메모장/개인 백업은 공유되지 않음. 기존에 공유된 예전 일정의 링크·체크리스트는 작성자가 원본을 다시 저장하면 새 형식으로 갱신됨.
5. **Mac 새 버전 자동 확인 팝업**: GitHub Releases의 최신 버전을 자동 확인하고, 새 버전이 있으면 알림 및 **Mac용 DMG 받기** 버튼 제공. 가능한 경우 버튼으로 DMG 직접 다운로드. **무료 ad-hoc 서명 상태에서는 DMG 설치/앱 교체까지 자동화하지 않음** (Apple Developer ID 서명 필요). 새 DMG 실행 시 macOS 보안 안내가 표시될 수 있음.

## 안전성 / 데이터

- 기존 Windows 및 Mac 버전의 앱 ID와 사용자 데이터 경로 변경 없음.
- 주말 타임라인 숨김 규칙 유지.
- 기존 사용자가 저장한 게임/연락처/일정 데이터를 자동 삭제하지 않음.
- Supabase `sharing_contacts`에 `group_name`, `auto_accept`, `auto_invite` 열 추가 및 신뢰된 초대 수락 함수 생성 완료. 모든 옵션 기본 `false`, 기존 연락처 그대로 유지.
- 인증서·비밀 Supabase 키는 프로젝트 클라이언트에 포함하지 않음. `sharing-config.json`에는 공개 가능한 publishable 키만 사용.
- 새 공유 필드(관련 링크, 체크리스트)는 초대 시 명시적 확인 후에만 서버로 전송.
- Windows/Mac 실제 GUI 검수와 두 개의 인증된 사용자 계정으로 초대 자동 수락/권한 테스트 필요.

## 배포

1. 현재 버전(v1.9.4)에서 JSON 수동 백업.
2. PATCH 압축을 GitHub 프로젝트 루트에 **폴더 구조 유지하며 덮어쓰기**.
3. `npm.cmd ci --no-audit --no-fund`, `npm.cmd test` (Windows PowerShell에서 npm.ps1 제한이 있으면 `npm.cmd` 사용).
4. GitHub Desktop Commit (`Add title editor, contact groups and Mac update notice v1.9.5`) → Push.
5. 최신 커밋에 `v1.9.5` 태그 생성 → Push. GitHub Actions Windows/Mac 빌드 확인.
6. 테스트용 계정 두 개로 보기/편집 권한, 그룹 일괄 초대, 자동 수락, 자세한 메모/체크리스트, Mac DMG 다운로드 검수.

## 개발자가 확인해야 할 제한

- 앱을 설치하기 전에 **업무용 실제 일정 대신 더미 일정으로 기능 검증**. 파일 패치 테스트는 통과했으나 실사용 통합 검증은 남아 있음.
- 이 버전의 Mac 지원은 **자동 알림+DMG 다운로드**까지이며 공식 `electron-updater`의 자동 설치 기능이 아님.
- GitHub Release 태그 v1.9.5가 이미 사용됐으면 재태그 대신 버전을 올려 배포.
