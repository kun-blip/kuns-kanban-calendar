# KUN'S KANBAN CALENDAR v1.7.2 — 자동 업데이트 팝업 수정

## 수정 목표

v1.7.1은 사용자가 "새 버전 확인" 버튼을 눌러야 업데이트 대화상자가 보일 수 있었습니다.
**v1.7.2부터는 설치된 Windows 앱을 켰을 때 새 버전이 확인되면, 버튼을 누르지 않아도 앱 안에서 팝업을 자동으로 엽니다.**

- 앱을 실행한 뒤 약 4초 후 GitHub Releases의 새 버전을 자동 확인합니다(네트워크 상황에 따라 완료까지 더 걸릴 수 있습니다).
- 새 버전이 발견되면 캘린더 화면에 "새로운 업데이트가 있어요!" 대화상자가 자동으로 열립니다.
- PC 시작 시 앱이 트레이에 숨겨졌다면 사용자가 창을 열 때 안내합니다.
- 다른 입력창에서 편집 중이거나 다른 팝업을 사용 중이라면 안내를 잠시 미룹니다.
- "나중에"를 누르면 **현재 실행 중에는 같은 버전 알림을 반복하지 않지만, 앱을 완전히 종료하고 다시 실행하면 다시 안내**합니다.
- 자동으로 다운로드하거나 강제로 종료하지 않습니다. 사용자가 설치를 선택합니다.
- 기존 Google Sheets 피드백 기능·일정·메모는 변경하지 않았습니다.

## 패치 적용 (v1.7.1 사용자)

1. 캘린더의 일정/메모를 JSON 백업합니다.
2. GitHub Desktop에서 `Fetch origin` / 필요한 경우 `Pull origin`을 실행합니다.
3. `Repository > Show in Explorer`로 실제 저장소 폴더를 엽니다.
4. `KUNS_KANBAN_CALENDAR_v1.7.2_PATCH.zip`을 압축 해제하고, **ZIP 내부의 폴더 구조를 유지한 채 저장소 최상위 폴더에 덮어씁니다**. `.git` 폴더는 건드리지 않습니다.
5. GitHub Desktop에서 변경 파일을 검토합니다. 특히 `package.json`과 `package-lock.json`의 버전이 모두 `1.7.2`여야 합니다.
6. `Fix automatic startup update popup v1.7.2`로 Commit 후 Push origin합니다.
7. History의 **가장 최신 커밋**에 `v1.7.2` 태그를 만들고 Push합니다.
8. GitHub Actions 성공, Releases에서 v1.7.2의 `.exe`와 `latest.yml` 게시를 확인합니다.

**이미 버전이 1.7.2로 수정되어 있으므로 `npm version 1.7.2`를 다시 실행하지 마세요.**

## 실제 검증 순서 — 중요

현재 설치된 v1.7.1에 수정된 코드가 없는 것은 정상입니다. 따라서:

1. 우선 기존 **v1.7.1 앱에서 수동 업데이트 확인 버튼을 사용하여 v1.7.2를 설치**합니다.
2. v1.7.2로 업데이트된 것을 확인합니다.
3. 저장소에서 `npm version 1.7.3 --no-git-tag-version`을 실행하고 Commit / Push / `v1.7.3` 태그 Push합니다.
4. GitHub Actions에서 v1.7.3 Release의 `.exe`와 `latest.yml`을 확인합니다.
5. 설치된 **v1.7.2 앱을 트레이에서도 완전히 종료한 후 새로 실행**합니다.
6. **새 버전 확인 버튼은 누르지 않습니다.** 인터넷 연결 상태에서 잠시 후 `v1.7.2 → v1.7.3` 자동 팝업이 나오는지 확인합니다.
7. "나중에"로 닫고, 트레이에서 완전히 종료 후 재실행해 다시 안내되는지 확인합니다.

## 테스트와 제약

- `npm test`: 총 42개 테스트 통과. 여기에는 새 버전 자동 팝업, 창 숨김/표시, "나중에", 다른 모달, 늦게 도착한 업데이트 이벤트 등이 포함됩니다.
- Linux 환경에서 코드와 모의 동작만 테스트했으므로 Windows NSIS 설치 후 실제 팝업 노출 및 GitHub 네트워크 동작은 아직 검증되지 않았습니다.
- GitHub 공개 릴리스가 정상이고 `latest.yml`이 존재해야 업데이트를 발견합니다.
- 기존 백업과 로컬 일정 경로는 수정하지 않았습니다.
