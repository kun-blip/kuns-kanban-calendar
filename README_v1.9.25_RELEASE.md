## 운영 배포 단계

1. `npm test` 전부 통과, GitHub 원격 v1.9.25 태그 부재 확인.
2. Supabase `slack_regina_companywide_owner_consent` 마이그레이션 적용 완료
   (2026-11-19, 원격 버전 `20261119081037`). `send_enabled=false` 유지.
3. 새 `slack-regina-dispatch` Edge Function v10 배포 완료.
   운영 잠금 및 RPC 인증·RLS·기존 데이터 확인. 실 자동 발송은 미활성화.
4. Windows NSIS 설치 파일을 빌드하여 설치·업데이트·팝업 직접 확인.
5. GitHub main에 검토된 변경사항을 푸시하고 v1.9.25 태그로
   GitHub Actions 릴리스 생성. 아티팩트 공개 및 자동 업데이트 확인.
6. 동료들이 앱에서 로그인해 **각자 자기 공유 일정의 알림 동의** 등록.
7. 동의 등록과 운영 승인 후 스케줄러 설정·이중 발송 스위치를 활성화.
   과거 이벤트 일괄 발송 금지. 새 일정 1건으로 검증한 뒤 정상 운영.

## 이번 릴리스에 자동으로 포함되지 않는 운영 변경

- 회사 Slack 채널에 자동 메시지를 보내는 스케줄러 활성화
- DB `public.slack_integration_control.send_enabled=true`
- Edge Function Secret `SLACK_SEND_ENABLED=true`

세 항목은 별도 운영 단계이며, 앱 배포만으로 자동 전송되지 않습니다.
