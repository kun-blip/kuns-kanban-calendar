# KUN'S KANBAN CALENDAR v1.9.20 — 스티커 기능 원복

## 승인된 팝업 패치노트

**01. 스티커 기능 종료**

팀 공용 스티커함과 날짜·일정 리액션 기능을 제거했어요.

**02. 캘린더 사용성 정리**

스티커 도입 이전의 간결한 캘린더 화면으로 복원했어요. 기존 일정과 공유 기능은 그대로 유지돼요.

## 핵심 내용

- v1.9.18의 검증된 화면/공유/업데이트 동작을 v1.9.20 버전으로 복원합니다. **앱을 1.9.18로 다운그레이드하는 것이 아닙니다.**
- v1.9.19 스티커 모듈, 화면 진입점, 날짜/일정 리액션을 제거합니다.
- v1.9.17 공유 일정의 작성자와 초대/권한 유지 개선, v1.9.18 최신 버전 확인 개선은 유지됩니다.
- 기존 사용자의 일정 데이터, 그룹, 연락처, 공유 기록은 삭제하지 않습니다.
- Supabase의 이전 스티커 테이블과 이미지 저장소는 **보존**합니다. 현재 앱에서는 사용하지 않습니다. 기존 스티커 업로드 데이터를 실제로 삭제하려면 별도 요청이 필요합니다.
- `supabase/migrations/20261103180000_team_stickers.sql`은 이미 적용된 데이터베이스 마이그레이션 이력으로만 보존하며 **다시 실행하면 안 됩니다**.

## 설치/배포 (기존 v1.9.19 로컬 프로젝트 기준)

1. 로컬 GitHub 원본 프로젝트 폴더 `C:\Users\master\Documents\GitHub\kuns-kanban-calendar`를 미리 백업합니다. 설치된 앱 폴더가 아닌 **소스 프로젝트 폴더**입니다.
2. `KUNS_KANBAN_CALENDAR_v1.9.20_PATCH.zip`을 프로젝트 폴더에 풀어 **덮어쓰기**합니다.
3. `RUN_v1.9.20_TESTS_CMD.bat` 실행합니다. 이 스크립트는 `APPLY_v1.9.20_ROLLBACK_CMD.bat`을 호출해 오래된 `renderer/stickers.js`, `desktop/sticker-utils.cjs`, `test/team-stickers-dev.test.cjs` 3개만 삭제합니다. **기존 일정 데이터는 삭제하지 않습니다.**
4. 테스트가 성공하면 `PUBLISH_v1.9.20_CMD.bat` 실행 후 `PUBLISH` 입력합니다. 배포 CMD는 v1.9.20 태그만 확인하고 기존 버전 태그를 건드리지 않습니다.
5. GitHub Actions의 Windows/macOS 결과와 GitHub Releases의 v1.9.20 파일을 확인합니다. 실제 설치 및 공유 일정/권한/업데이트 동작을 동료 PC에서 확인합니다.

### 주의 사항

- 실제 GitHub 배포는 CMD를 실행하기 전까지 진행되지 않습니다.
- 테스트 실행 도중 삭제하는 세 파일은 앱 코드 파일뿐입니다. 사용자 PC의 저장 데이터/AppData와 Supabase 서버 데이터는 절대 정리하지 않습니다.
- 기존 원본 로컬 프로젝트가 이미 v1.9.20 다른 개발본으로 변경되어 있다면, **전체 소스 ZIP을 별도 폴더에 풀어 비교한 뒤** 적용해 주세요.
- `v1.9.19` 이상 사용자는 설치형 자동 업데이트를 통해 `v1.9.20`으로 올라가야 하며, 더 낮은 버전으로 설치하면 안 됩니다.
- macOS는 기존 정책대로 새 버전 안내 및 다운로드 링크를 사용합니다.

## 검증

- 활성 스티커 앱 코드가 제외되었는지 확인하는 자동 테스트 포함.
- v1.9.19 버전에서 덮어쓴 패치에 대해 삭제 CMD 실행 후 자동 테스트를 재실행하도록 검증.
