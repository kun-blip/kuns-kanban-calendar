# KUN'S KANBAN CALENDAR v1.9.17 — 공유 일정 정보 유지 개선

기준: v1.9.16 정식 프로젝트. v1.9.16에서 저장한 공유 일정의 작성자·참여자·초대 권한을 다음 버전에서도 유지하기 위한 호환성 보완입니다.

## 확정 패치노트

1. **공유 일정 정보 유지 개선** — 기존 공유 일정의 작성자 및 초대·권한 정보가 다음 버전에서도 안정적으로 유지되도록 보완했어요.
2. **공동 편집 안정성 개선** — 동료가 공유 일정을 수정해도 기존 작성자 정보가 유지되도록 개선했어요.

## 기술적 변경

- 공유 일정에서 작성자 정보를 수정 화면의 입력값이 아닌 **서버의 기존 `ownerEmail`** 값으로 유지합니다. 동료가 편집할 때 기존 서버 메타데이터도 보존합니다.
- 서버에서 최신 공유 일정 정보 조회에 실패하면 작성자 데이터를 덮어쓸 위험이 있는 수정 요청을 보내지 않습니다.
- 기존 참여 동료, 역할(보기/편집), 수락 대기 초대는 초기화하거나 재발송하지 않습니다.
- v1.9.16 데이터 형식과 앱 사용자 데이터 저장 경로는 유지하며 서버 스키마 변경은 없습니다.

## Windows CMD 배포 절차

1. 원본 프로젝트 폴더(`C:\Users\master\Documents\GitHub\kuns-kanban-calendar`)를 백업합니다. 이 경로는 설치형 앱이 아닌 GitHub 프로젝트 소스입니다.
2. `KUNS_KANBAN_CALENDAR_v1.9.17_PATCH.zip` 내부 내용을 **프로젝트 루트(package.json이 있는 폴더)**에 덮어씁니다. 압축 해제 시 별도의 상위 폴더를 만들지 마세요.
3. `RUN_v1.9.17_TESTS_CMD.bat` 실행 → 테스트 전부 통과 확인.
4. `PUBLISH_v1.9.17_CMD.bat` 실행 → 변경 파일 및 Git 상태 확인 → 정확히 `PUBLISH` 입력.
5. GitHub Actions의 Windows·macOS 빌드 성공 및 v1.9.17 릴리스 파일 업로드 여부를 확인합니다.

기존에 Git에 등록 대기 중인 파일이 있으면 배포 스크립트는 중단합니다. 확인할 때는 `git diff --cached --name-only`, 등록 대기만 해제하려면 `git restore --staged .` 입니다. `git reset --hard`나 `git clean -fd`를 사용하지 마세요.

## 배포 후 필수 실사용 검수

- v1.9.16에서 미리 생성한 '공유 유지 테스트' 일정을 **삭제하거나 새로 만들지 않은 상태로** v1.9.17에서 엽니다.
- 작성자 이메일, 참여 중인 동료, 보기/편집 권한, 수락 대기 기록이 유지되는지 비교합니다.
- Windows에서 날짜를 수정하고 Mac 동료 계정에서 동기화해 변경 날짜와 작성자가 유지되는지 확인합니다.
- 편집 권한이 있는 동료가 일정을 수정한 뒤, 원래 작성자가 바뀌지 않았는지 확인합니다.

### 검증 범위 주의

자동 테스트는 모의 공유 서버 데이터로 수행합니다. 실제 서버에 저장된 사용자의 테스트 일정이나 Windows·Mac 실제 동기화 결과는 이번 패키지 생성 과정에서 읽거나 변경하지 않았습니다. 저장돼 있지 않은 과거 작성자 정보는 이 버전에서 임의로 복구하지 않습니다.
