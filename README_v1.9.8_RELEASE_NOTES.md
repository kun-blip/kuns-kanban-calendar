# KUN'S KANBAN CALENDAR v1.9.8 — 업데이트 패치노트

## v1.9.8 앱 팝업에 실제로 표시되는 내용 (확정 문구)

**그룹 초대 및 동료 관리 개선**

1. **그룹 전체 일괄 초대** — 동료 그룹을 선택하면 구성원 전체를 한 번에 일정에 초대할 수 있어요.
2. **그룹별 보기/편집 권한 설정** — 초대하는 그룹마다 보기만 또는 편집 권한을 간편하게 설정할 수 있어요.
3. **동료 목록 접기/펼치기** — 동료 관리에서 그룹별 구성원 목록을 접고 펼쳐 더욱 깔끔하게 관리할 수 있어요.

> 위 세 문구는 사용자 지정 패치노트이며, 기존 v1.9.7에서 개선된 기능의 설명을 포함합니다. 앱 업데이트 후 패치노트가 나타나는 기능 자체는 v1.9.8에서 새로 추가됩니다.
> 다음 버전부터는 업데이트 파일을 제작하기 **전에** 패치노트 내용을 사용자에게 먼저 확인받아 확정해야 합니다.

## 새 기능

- **업데이트 후 처음 실행하면 자동으로 패치노트 표시**: 기존 v1.9.7(또는 그 이전) 사용자가 v1.9.8로 업그레이드하고 앱을 다시 열면 `v1.9.8 업데이트 패치노트` 팝업이 나타납니다.
- **버전별 1회 안내**: `확인했어요`, 닫기(X), Escape를 누르면 해당 버전을 확인한 것으로 기록하며, 이후 같은 버전에서는 자동으로 다시 열리지 않습니다. 저장 오류가 나면 닫히지 않고 재시도를 안내합니다.
- **새로 설치한 사용자는 환영 화면 우선**: 기존 설치 데이터가 없는 경우 패치노트가 자동 표시되지 않습니다.
- **방해 없는 표시 시점**: 트레이 백그라운드 실행, 첫 실행 도움말, 다른 모달, 일정 편집 중에는 자동 표시를 미루고 앱을 확인할 수 있을 때 표시합니다.
- **언제든 다시 확인**: 상단 **업데이트** → **패치노트 보기**. 팝업의 버전 선택에서 `v1.9.7` 변경 내역도 볼 수 있습니다.
- **기존 데이터 보호**: 표시 상태는 사용자 데이터 폴더의 `release-notes-seen.json`에 따로 보관됩니다. 일정, 메모, 동료 그룹 및 초대 데이터는 수정하지 않습니다.

## 기존 GitHub 저장소에 적용하기 (CMD)

1. `KUNS_KANBAN_CALENDAR_v1.9.8_PATCH.zip`의 파일들을 **현재 Git 프로젝트 최상위 폴더** (`package.json`이 있는 폴더)에 압축 해제하여 같은 경로에 덮어씁니다. **기존 v1.9.7 ZIP 전체를 다시 덮어쓰지 마세요.**
2. `RUN_v1.9.8_TESTS_CMD.bat` 실행 후 `pass 106` / `fail 0` 확인.
3. `PUBLISH_v1.9.8_CMD.bat`을 실행하고 목록에 이번 변경 파일만 포함됐는지 확인. 마지막에 대문자 `PUBLISH`를 입력합니다.
4. GitHub Actions에서 Windows 빌드 성공, Release에 `v1.9.8`이 올라왔는지 확인합니다.
5. 설치된 v1.9.7 Windows 앱에서 새 버전을 다운로드/적용하고 재시작해 **패치노트 자동 표시**를 확인합니다. 닫고 다시 앱을 실행해 자동으로 반복되지 않는지 확인해 주세요.

> 테스트 스크립트는 배포하지 않고, 배포 스크립트는 명시적인 `PUBLISH` 입력이 있어야 푸시합니다. macOS 빌드는 기존 GitHub 워크플로에 따릅니다.

## 수정 파일

- `desktop/release-notes-state.cjs`, `desktop/release-notes.json`: 버전 비교 및 버전별 내용
- `desktop/main.cjs`, `desktop/preload.cjs`: 시작 시 기존 설치 판단, IPC, 확인 상태 영구 저장
- `renderer/release-notes.js`, `renderer/index.html`, `renderer/update-center.js`: 자동/수동 패치노트 UI, 모달 충돌 방지
- `package.json`, `package-lock.json`: v1.9.8 버전
- `test/release-v198.test.cjs`, `test/release-v196.test.cjs`: 새 기능 검증 및 이전 회귀 테스트 버전 호환성

## 향후 버전에서 패치노트 작성하기

새 버전을 출시할 때마다 `desktop/release-notes.json`에 `"1.9.9"` 같은 버전과 `heading`, `items` 배열을 추가한 뒤 패키지 버전을 올리면 됩니다. 업데이트 직후 해당 버전의 새로운 항목이 표시됩니다. 별도의 서버 설정이나 외부 서비스는 필요 없습니다.
