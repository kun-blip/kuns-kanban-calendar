# KUN'S KANBAN CALENDAR v1.9.0 — 선택 일정 공유 시험판

## 주요 기능
- 이메일 인증(OTP) 후 선택한 일정만 Supabase 서울 리전으로 공유
- 공유하기 → 일회용 초대 링크/코드 생성(7일 만료) → 초대 수락
- 초대받은 일정은 읽기 전용으로 달력 표시. 개인 일정·메모·Todo 및 백업 파일은 서버에 업로드하지 않음
- 공유한 원본 일정의 상세 내용/드래그 수정이 서버에 반영, 앱 실행·창 활성화·2분마다 서버의 최신 내용 조회
- 초대 코드 취소, 공유 중단, 받은 일정에서 나가기
- 사용자 인증 토큰은 앱 데이터의 `sharing-auth.json`에 따로 보관. 백업 JSON에는 포함하지 않음

## 배포 전에 반드시 확인
1. **Supabase Authentication → Providers → Email** 활성화. 이메일 OTP 안내문에 링크만 보이는 경우 Supabase Email Templates에서 `{{ .Token }}`도 안내하도록 변경.
2. 기본 Supabase 메일 발송은 외부 수신자 및 발송량에 제한이 있으므로 **동료 이메일 인증을 위해 커스텀 SMTP 설정**이 필요할 수 있습니다. 비밀번호/API Secret을 앱에 넣거나 GitHub에 Push하지 마세요.
3. 회사 정책에서 업무 일정 제목, 기간, 상세 메모의 외부 서버 저장이 허용되는지 확인하세요.
4. Supabase Security Advisors 경고를 점검하세요. `app_private.shared_event_invites`는 비공개 스키마와 GRANT 회수로 직접 접근을 막았으나 RLS 미적용 경고가 남습니다. 정책 승인 후 별도 정비가 필요합니다.
5. 현재는 앱의 공유 초대/공유 중단/조회/수동 로그인을 제공하는 **시범 기능**으로, Windows/Mac 실사용 2계정 테스트가 완료되지 않았습니다.

## 테스트 절차
1. PC A에서 `일정 공유` 클릭 → 이메일 인증 → 개인 일정 선택 → `동료 초대` → 공유 시작 → 초대 링크 복사
2. PC B에서 `일정 공유` → 다른 이메일 계정 인증 → 초대 코드 붙여넣기 → 수락
3. PC B 달력에서 읽기 전용 일정 확인. PC A에서 원본 변경 후 PC B에서 앱 포커스를 전환하거나 2분 기다려 확인
4. PC A에서 공유 중단한 뒤 PC B에서 일정이 사라지는지 확인
5. 개인 JSON 백업에 타인의 공유 일정이 포함되지 않는지 확인

## 주의
- 링크 `kuuns-kanban://invite/…`는 앱이 설치되어 프로토콜이 등록된 환경에서만 바로 열립니다. 안 되면 초대 코드를 앱에 붙여넣으세요.
- 이 버전에서는 공유 일정의 반복/게임 아이콘/체크리스트/링크/알림은 공유하지 않습니다. 제목, 날짜, 상세 메모, 상태, 색상만 전송됩니다.
- 서버 변경 중 네트워크가 끊기면 사용자에게 오류를 알리고 나중에 다시 동기화해야 합니다.
- Windows 기존 자동 업데이트 지원, macOS 비공증/임시서명 DMG 상태는 동일합니다.
