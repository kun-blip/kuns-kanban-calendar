# KUN'S KANBAN CALENDAR v1.9.14 — 태그 관리 업데이트

기준: v1.9.13 GitHub 프로젝트 소스. 승인된 패치노트 두 항목을 그대로 사용합니다.

## 앱에 표시할 패치노트

1. **일정 태그 관리 기능 추가** — 한 번 생성한 태그를 저장하고 재사용할 수 있습니다. 태그 이름과 컬러를 자유롭게 수정하고 관리할 수 있어요.
2. **일정 생성 UI 개선** — 기존 상태 선택 영역을 태그 관리로 변경하고 일정 제목 바로 아래에 배치했습니다.

## 반영 내용

- 생성한 태그를 PC 로컬 태그 라이브러리에 저장하고 다음 일정에서도 클릭만으로 선택·해제합니다.
- 태그 이름과 색상을 수정하면 같은 태그가 적용된 로컬 일정에도 반영하며, 공유 일정 동기화를 시도합니다.
- 저장된 태그를 삭제해도 이미 작성한 일정의 태그 기록은 보존됩니다.
- 일정 폼의 상태 선택을 태그 관리로 바꾸고 제목 바로 아래에 배치했습니다. 기존 상태 기록은 데이터에 유지합니다.
- 백업 내보내기 및 가져오기에서 태그 목록과 삭제한 태그 표시 제외 설정을 유지합니다.
- 기존 @태그 + Enter 입력 및 일정별 색상 설정은 유지합니다.

## CMD 배포 절차

1. `KUNS_KANBAN_CALENDAR_v1.9.14_PATCH.zip` 압축을 기존 프로젝트 루트에 **덮어쓰기**합니다. `package.json`과 `.github` 폴더가 같은 위치입니다.
2. `RUN_v1.9.14_TESTS_CMD.bat`을 실행해 Node.js 구문 확인 및 자동 테스트 통과를 확인합니다.
3. `PUBLISH_v1.9.14_CMD.bat`을 실행합니다. `git status`의 변경 파일을 검토한 뒤 `PUBLISH`를 입력합니다.
4. GitHub Actions가 정상 완료되고 v1.9.14 Release 파일이 생성되면 실제 Windows/macOS 앱에서 태그 저장·재실행·재사용을 검증합니다.

Git에 이미 등록된 파일이 있으면 스크립트가 중단됩니다. `git diff --cached --name-only`로 검토한 후, 별도 커밋할 변경이 아니라면 `git restore --staged .`로 스테이징만 해제할 수 있습니다.

## 유의사항

- 태그 라이브러리는 **기기별 로컬 앱 데이터**에 저장됩니다. 공유 일정에 실제로 부착된 태그는 동기화되지만 미사용 태그 목록 자체는 동기화되지 않습니다.
- 로컬 및 자동 테스트와 macOS 실기기 테스트는 다른 과정입니다. 앱 업데이트/공유 동기화는 배포 후 직접 확인해야 합니다.
- GitHub Actions 성공 전에는 배포 성공으로 보지 마세요.
