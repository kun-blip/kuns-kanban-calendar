# v1.9.1 동료 연락처 및 공동 편집 (시험 배포)

## 적용 순서
1. v1.9.0 앱에서 개인 JSON 백업을 만듭니다.
2. PATCH ZIP 내부를 기존 GitHub 프로젝트 폴더에 덮어씁니다.
3. GitHub Desktop에서 변경 파일을 확인하여 Commit, Push한 후 최신 커밋에 `v1.9.1` 태그를 만들고 Push합니다.
4. Actions에서 Windows/macOS 빌드를 확인합니다. 기기에 설치 후 테스트용 계정 두 개로 검수합니다.

## 기능
- 상단 '일정 공유'에서 로그인, 동료 닉네임/이메일 등록, 수정, 삭제
- 새 일정 / 기존 일정 수정창 내 닉네임 검색, 여러 명 선택, 각 동료별 보기/편집 권한 지정
- 초대받는 사람은 앱의 '받은 초대'에서 수락 또는 거절 (SMTP를 통한 별도 이메일 초대 발송은 미구현)
- 기존 64자리 초대 코드 유지
- 소유자는 참여자의 역할 변경 및 제거, 미수락 초대 취소 가능
- 수락한 편집자는 공유 관리창에서 제목, 날짜, 메모 및 진행 상태를 수정 가능
- 최종 공유 내용의 기준은 Supabase. 2분마다 / 앱 포커스 시 동기화
- 공동 수정은 `revision` 조건으로 충돌을 거부. 자동 병합은 하지 않음
- 개인 링크, 체크리스트, Daily Todo, 기존 개인 메모는 원격에 자동 업로드하지 않음

## 주의
- 기존 v1.9.0의 개인 일정은 소유자 PC에 그대로 저장. 서버에서 공유 필드만 로컬에 반영할 수 있습니다.
- 일정 저장 직후 서버 전송 실패 가능: 실패 메시지가 나와도 로컬은 저장됨; 공유 여부를 재확인하세요.
- 연락처는 공개 사용자 검색 기능이 아니며 작성자가 입력한 이메일만 저장합니다.
- 이름/이메일이 실제 Supabase 로그인 계정과 일치해야 받은 초대에 표시됩니다.
- 이미 v1.9.0으로 수락한 초대코드의 멤버는 '보기만' 기본 권한입니다.
- 정식 배포 전 사용자 간 인가 우회 / 동시 수정 / 오프라인 실패 처리를 실제 계정으로 검수해야 합니다.
- 앱은 현재 GitHub에 자동 배포되지 않았습니다. 서버 마이그레이션은 연결된 Supabase 프로젝트에 적용했습니다.
- 보안 경고: `app_private.shared_event_invites`의 RLS 활성화 여부와 SECURITY DEFINER RPC 12개의 권한은 별도 재점검 과제입니다. 그 전에는 회사 전체 공개 배포 금지.

## 필수 테스트
1. 서로 다른 이메일 A/B 로그인, 연락처 추가, 닉네임 검색 → Viewer 초대 → B 수락
2. Viewer B는 공유 일정을 볼 수 있으나 편집이 차단되는지 확인
3. A가 B에 Editor 권한 부여, B가 수정하고 A에서 동기화 확인
4. A/B가 같은 버전으로 수정 시도, 두 번째 저장이 충돌 메시지로 거부되는지 확인
5. 초대 거절, 취소, 참여자 내보내기, 재초대, 로그아웃/재실행 확인
6. 기존 비공유 일정·Todo·메모·JSON 백업 불변 확인
7. Windows/macOS 양쪽 확인
